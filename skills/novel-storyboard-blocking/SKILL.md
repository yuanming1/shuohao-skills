# novel-storyboard-blocking-02 · 站位与空间

**使用顺序：02，按需执行。** 调用使用 `$novel-storyboard-blocking`。承接 01 的分镜初稿，解决人物站位、机位、路径与遮挡，并以彩色人偶宫格表达人物调度，再进入 03 的情绪与镜头增强、04 的动作与连续状态复核。
已有完整空间安排时可以跳过本步；后续调整摄影或动作影响空间关系时，返回核对受影响镜头。编号不是安装依赖，可以直接处理用户提供的已有分镜。

在分镜初稿完成后、正式出图与视频生成前执行。已有图片时同样可以复核，但空间修改可能需要重出受影响的关键帧。
直接更新项目唯一正式分镜 `storyboard.json`，沿用已有实际文件名；不创建 `-blocking.json` 或其他分镜版本。后续增强、动作复核、报告合成和画布导出均继续读取同一路径。宫格与报告属于派生产物，需要时从正式文件重新生成。
`{baseDir}` 是本文件所在目录。本技能自包含，只有 Python 标准库依赖；无需读取其他技能，也不启动 Blender。

## 1. 确定故事与范围

读取用户项目的 `storyboard.json` 和对应 `script.json`，有场景、角色、道具设定或参考图片时一起读取。
有 `staging.json`（novel-staging 的产出）时一并读取，它带来两类既定事实，本技能不重新决定：

- **认图物件清单**：每个地点 4–20 件能坐能站的东西及其俯视位置（`items` 的 `plan`、`side`、`on`）。空间规划以它为准——站位、机位锚点、遮挡只引用清单里的东西；清单里没有的高台、立柱不进任何承接说明。
- **每场开场站位**：在场的每个人在哪件东西哪一侧、坐站、朝向与群演（`places`、`extras`）。这一场第一段段级 `blocking` 的开场部分照抄它写全，本技能从这一刻往后承接；缺了 staging（或某场未覆盖）才由本技能按既有规则规划开场，并在首切接镜说明里写明依据。

先确认剧本动作，再处理指定的集或段。没有剧本时，可以导出已有完整分镜的站位宫格，但不能自行为缺项补写剧情。

使用本技能时先阅读 [references/spatial-continuity.md](references/spatial-continuity.md)。
固定场景关系来自已确认的场景设定；没有规定、但拍摄需要的位置可作为调度选择明确写入分镜。
不要把未见过的场景图片、未测量的距离或模型设想说成已经验证的事实。

## 2. 先规划空间，再写画面与动作

复用已有字段，不扩展上游 JSON schema：

| 位置 | 必须明确的内容 |
|---|---|
| 段级 `blocking` | 场景锚点、人物开场位置、姿态朝向、持物和关系轴；在原开场事实后追加人偶颜色对应、逐镜路径与调度参考用途，导出至【人物关系与构图逻辑】。画面左右只约束首镜；有 staging 时保留其原开场句 |
| 逐镜构图字段 | `cameraPosition` 说明在什么锚点一侧、朝谁拍、角度；`composition` 说明前后景、主体画面位置；`eyeline` 说明看向谁或什么。同步既有 `lens`、`focus`、`stability` |
| `cut.note` | 使用“起始：…；动作：…；结束：…；接镜：…”记录每切状态变化；首切说明开场，连续下一段承接上一段结尾 |
| `cut.frame` | 从本镜机位可见的单一切点状态，含中文景别与角色名；围绕主要观看对象写清必要的位置、姿态、视线、遮挡和持物关系 |
| `cut.shot` 与 `h3Prompt` | 从对应切点开始的动作、终态与接镜，使用通用身份。H3 对应镜头也必须逐一同步，不能只改 `shot` |

先完成前三项，再同时写后两项。有既定移动时，按空间规则核对沿途参照、遮挡变化和终点可见性；固定机位也要检查主体移动后的画面。将空间修订融入原有画面与动作描述，合并重复说明；完整布局与推导留在站位和备注中。不要只在宫格提示词里新增站位，也不要把整段布局机械粘到每张关键帧里。
分镜中的景别、时长、顺序、台词和节拍认领沿用原稿；如果发现上游剧情缺少必要动作，明确指出缺口再处理，不能靠下一镜“已经完成”补造过程。

### 彩色人偶与人物路径写回

宫格主要提供人物调度参考。左侧站位图和右侧每格都将可见角色替换成简化、单色的人偶，保持原镜号、景别、姿态、持物和接触关系。不同角色使用容易区分的颜色，同一角色在项目各段保持同色；颜色不取自真实肤色或服装，也不代表情绪。人物外貌与服装仍由角色设定图决定。

根据已有角色 ID 与姓名确定对应关系，将以下三个区块追加在正式 `storyboard.json` 的段级 `blocking` 原开场事实后；不改 staging 句，不新增 JSON 字段。每个角色一行，逐镜路径使用该段实际镜号：

```text
【调度人偶对应】
- C01 快递员：蓝色人偶
- C02 店员：橙色人偶
【调度路径参考】
- E01-01-f1：蓝色人偶双手托箱，从西侧入口沿柜台外侧通道走到柜台前停下；橙色人偶留在柜台内侧。
- E01-01-f2：两人位置保持；蓝色人偶原地放下纸箱后松手，不重复走近。
- E01-01-f3：两人在画外保持原位，纸箱留在台面。
【调度参考用途】
本段附有调度宫格时，按上述颜色人偶对应实际角色，参考相应镜号的站位、朝向和人物移动路径完成调度；路径只在对应镜头发生，已完成的移动不重演。人偶颜色仅用于识别角色，实际人物的脸、服装和外貌沿用角色设定；图中箭头、标签及宫格边框不进入成片。尚未提交该图时，以本段文字调度为准，不声称已参考图片。
```

示例来自本技能自有故事；实际角色、颜色和路径沿用当前项目。没有人物时对应区块写“本段无人出场。”；有人但没有位移时路径区块可写“本段无人物位移。”，不虚构箭头。有人移动时按镜号分别交代谁移动、起点、既定通路、方向和停点，保留同镜其他人物的状态。朝向标记与移动箭头分开；同一人物的路径沿用其颜色，不把多个时刻的人偶画成多个角色。
`cut.note`、`shot` 与 H3 同步实际路径与终态；真实关键帧的 `frame` 继续描述真实角色，不把人偶配色写成演员外貌。完整绘图标记只进入调度图，必要空间事实仍进入关键帧正文。

## 3. 按真实消费端同步并复核

阅读 [references/downstream.md](references/downstream.md)，依次对照：

- **关键帧**：出图实际消费 `cut.frame`，不会自动读取 `blocking`、`cut.note` 或本技能交接包。镜头语言必须已进入画面正文。
- **Seedance**：现有导出器将 `blocking` 写入【人物关系与构图逻辑】，颜色人偶对应、逐镜路径与调度用途必须在这里可读；动作与终态同时写入 `shot`，备注本身不会变成视频指令。
- **H3**：使用单独编写的 `h3Prompt`；逐镜同步人物起始、动作与终态。实际附带调度图时说明颜色对应与路径用途，按已有协议确认附件职责；保留原关键帧图片对应关系、切点时刻、台词和提示词语言。
- **已生成的图片**：核对真实画面，受修改影响的图片列为待更新。用户没有要求出图时交付待更新清单，不宣称图片已经同步。

逐镜反向复核剧本、站位、机位、`frame`、`shot`、H3 正文及跨段边界。程序只检查材料齐备，不能代替这一步。
有项目原有校验工具时按现有入口运行；它们属于项目工作流，不是本技能的运行依赖。

## 4. 导出彩色人偶调度宫格

```bash
python {baseDir}/scripts/blocking.py export \
  --storyboard <项目-storyboard.json> --segment E01-02 --out <预演目录>
```

可选 `--ep 1`、`--aspect 9:16`、`--frames <关键帧目录>`。不指定范围时处理全部分段；单镜列为待补说明，不制作宫格。
参考图片可省略；支持 `<段号>-f1.png`、`<段号>/<段号>-f1.png` 和上游原生的 `<段号>/f1.png`，以及 JPG/JPEG/WebP。
存在多个版本或空文件时报告缺项，不擅自选择。缺少站位、机位、构图、视线、动作正文、四段承接说明或切点描述时，回到前面的规划步骤处理。
缺少人偶对应、路径说明，出现同段共色、同角色多色或跨段颜色冲突时同样列为待补。旧交接包需先补齐这两项约定，不能静默猜测颜色后交付与视频正文不同的版本。

输出 `<预演目录>/_blocking-grid/<段号>/` 下的 `grid-input.json`、`grid-prompt.txt`、`grid-brief.md`；汇总为 `_blocking-grid/index.json`。
缺项段只输出 `grid.todo`，退出码 2；输入错误为 3。重新导出先将所选段旧交付保存为 `.stale`，未选中的段不受影响。
交接包可以单独复制，通过 `export --plan <grid-input.json> --out <另一个目录>` 重导出；结构说明见 [references/package.md](references/package.md)。

左侧展示开场布局与颜色图例，后续移动以同色路径、镜号及起终点标注；右侧保留原镜号、实际时长及切点状态，人物统一使用对应颜色人偶。
无图时可交付完整提示词；已有真实关键帧只提供空间、姿态、接触和机位依据，绘图时将人物转成人偶。实际出图需用户明确要求和可用图像工具。
生成后可将该图作为单独的人物调度参考提交给支持该用途的生成接口，并按实际附件绑定说明角色与路径职责。图像路径或文字提及不会自动提交图片；不更改既有关键帧编号，成片人物仍由角色设定确定。

### 已有交接包的调度信息写回

默认由 Agent 按上述工作流原位更新正式分镜。已有 `grid-input.json` 中补好的颜色与路径说明，也可以通过以下命令写回该段 `blocking`：

```bash
python {baseDir}/scripts/blocking.py sync-dispatch \
  --storyboard <项目-storyboard.json> --plan <grid-input.json>
```

命令只更新 `blocking` 的调度约定，保留原开场事实、其他集段、镜头与未知字段；校对包与正式分镜的镜号、时间、画面、机位、动作及承接，并核对跨段颜色一致性。旧包或原站位不一致时拒绝写入；材料缺项返回 2，输入或版本不一致返回 3，通过后原位更新返回 0。
该命令不会从图片自动识别路径，也不会修改 H3、生成图片或添加附件。实际调度变化仍需先同步正式逐镜正文与 H3；颜色与路径写回后，从正式分镜重新导出宫格和视频提示词，不能继续使用旧交付。

样例先确定 [examples/雨棚取件-story.md](examples/雨棚取件-story.md) 的故事，再制作同目录交接包；不借用其他技能的样例。


## fork 同步边界

所有能力位于本目录，不修改上游技能、安装脚本、报告组装器或默认导出路径。
通过显式使用本技能接入；普通分镜流程不会自动多出这个步骤。
上游数据格式变化时，先更新本目录的输入适配及自测。未来若上游出现同名目录仍可能产生合并冲突，不能保证永远零冲突。
