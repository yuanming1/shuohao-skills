# 空间规划与逐镜承接

学习来源：用户提供的梦源 AI“站位图预览”截图，提取“左侧开场站位、右侧逐镜画面”的联览方式；
同一源安排贯通关键帧与视频的工作流来自本项目使用需求。以下规则已内化，本文件不依赖外部技能。

## 场景位置与画面位置分开

先明确不会随机位变化的关系：人物在柜台内侧还是外侧，门在柜台哪一端，谁挡住谁，手里是什么。
再从每切机位推导画面左右、前后景、视线与遮挡。不能把首镜“甲在左、乙在右”当成整段每个机位都必须照抄的平面坐标。
没有位移动作时，改变构图应调整机位，不能把人物搬到新的位置。

段级 `blocking` 记录开场。当前段的走近、坐下、松手和交接属于相应切的状态变化，不能让全段始终复用开场姿态。
同场连续下一段从上段结束状态出发；换场、时间省略或回忆需要剧本依据。

## 开场站位来自 staging（有则照抄）

上游给了 `staging.json`（novel-staging 的产出）时，每场开场的「谁在哪、坐站、朝向、群演」已经定了：
走位句（`blocking` 命令的产出）就是事实，这一场第一段段级 `blocking` 照着它写全，不改内容本身——发现与剧本冲突先向用户指出，不悄悄改站位。
认图物件清单（地点的 `items`）同时是场景锚点的权威来源：机位「在什么锚点一侧」、遮挡「被什么挡住」优先引用清单里的东西；
图里看不到、清单里没有的物件不进任何承接说明。staging 未覆盖的段（续场、时间省略、回忆）仍由本技能按既有规则规划开场，首切的接镜说明写明依据。

本技能用到的 staging.json 字段（格式来自上游 novel-staging，此处只列读取所需的最小集）：

| 层级 | 字段 | 含义 |
| --- | --- | --- |
| 地点 | `readFrom` | `picture`＝看着场景图认的；`prompt`＝没有图、按提示词推算的草稿（引用时向用户注明） |
| 地点 | `items[]` | 认出的东西：`name`、`plan`（俯视位置 0–1）、`on`（能坐能站）、`round`（俯视是圆的） |
| 场 | `places[]` | 出场人物每人一条：`present`（开场在不在）、`item`＋`side`＋`along`（哪件东西哪一侧、沿侧位置）、`posture`（坐 / 站）、`facing`（八方位） |
| 场 | `extras` / `extrasWhere` | 群演人数与所在位置；0 时 `extrasWhere` 为 null |
| 场 | `blocking` 命令产出 | 每场一句开场走位句，第一段段级 `blocking` 照抄它写全 |



## 先写一份状态安排

每切 `cut.note` 使用四个标签，冒号可以为中文或英文：

- 起始：切点处的位置、朝向、姿态、接触关系及关键持物。
- 动作：本切实际认领的动作与先后顺序。
- 结束：哪些状态改变，哪些保持。
- 接镜：承接上一切的哪个状态；首切说明开场依据。

只记录影响连续性的事实。静态问答无需虚构移动；普通镜头无需增加无关的精确坐标。
接触与持物变化必须有可见过程：拿着变成放下、搀扶变成松开、站着变成坐下，都不能只写在下一镜的起始说明里。
画外仍然存在的人或物不应被自动移除；不在画面里也不等于必须写进每张关键帧。

## 机位必须能解释画面

“平视正面”只说明角度；涉及空间承接时还需要说明从哪个场景锚点一侧朝谁拍。
正反打以两人的关系线或动作方向确定轴线，再说明机位侧。不要给所有场景画一条没有依据的“180°线”。
有意越轴可以成立，但要在镜头中有可识别的重新定向、连续运动或叙事依据；不能由示意图擅自补镜头。

逐镜核对：

1. `cameraPosition` 所在一侧是否能看到 `frame` 中的人物与道具？
2. `composition` 的前后景、画面位置是否与这一机位相容？
3. `eyeline` 是否符合双方站坐高度、目标位置及当前动作？
4. 上一镜结束是否能推出本镜起始？移动路径是否被已知家具或门框截断？

这些是 Agent 或人工需要执行的语义判断。标签齐全、导出成功、图片好看都不能替代判断。

## 同一安排的三种表达

`frame` 只写切点处的一个可见状态；不能同时写走来、递交、接过、转身离开的全过程。
`shot` 从这个状态继续，写动作过程与结束状态；H3 对应镜头说同一件事，按原协议写参考图片和时间。
布局图从这些事实派生：开场图对应 0 秒，路径对应明确的镜号，右侧格子各自对应原切点。

发现冲突时先改分镜源文件，再同步关键帧和视频正文，最后重导出宫格。
只改图里的箭头或图像生成提示词，会让正式投产继续使用旧安排。
