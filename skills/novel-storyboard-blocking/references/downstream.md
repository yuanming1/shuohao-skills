# 空间安排如何进入关键帧与视频

本文件说明本项目已有的数据消费关系。内容自包含；不要求安装或读取其他技能。

## 关键帧出图

关键帧出图消费 `cut.frame`；现有画布导出器将它原样写入图片节点提示词。
先确定本镜主要观看对象或人物关系，再将理解这一切点所需的空间事实写入 `frame`：中文景别、角色名、可见位置与姿态、视线，以及必要的持物、接触和遮挡。完整场地布局留在 `blocking`，空间推导与待核实项留在 `note`；画外锚点不必为了说明方位而进入画面。

空间修订应替换原有对应描述、合并同义内容，形成一份完整画面；不要在正文后再附一套站位、机位和构图说明。每次独立出图仍应携带本镜必要的空间事实与参考，不能假定模型读取过其他节点。
人物外貌和场景造型由实际提交的参考图提供；已经绑定构图图时简要说明其职责，并写明当前状态与必要例外。不把角色设定图的站姿当成剧情姿态，也不引用实际未提交的站位图。

## Seedance

现有程序从段级 `blocking`、逐镜构图字段与 `shot` 组装视频提示词，剧本台词仍由原有流程逐字提供。
`cut.note` 是规划与复核依据，不会自动变成视频动作。

`shot` 使用通用身份，写运镜、主体动作、位置变化及终态；不写角色姓名、图片编号、镜头编号或精确切点秒数。
一个镜头保持一个主运镜，原有音效、配乐与台词协议继续沿用。
开场 `blocking` 不表示人物全段静止：发生变化的镜头要在 `shot` 里明确写出路径、停点、转向和接触变化。

## MiniMax H3

`h3Prompt` 是单独编写的整段文本，不会因为修改 `shot` 或 `blocking` 自动刷新。
对每个 `[Shot k]` 同步以下内容：引用对应 `<Picture k>` 的切点状态、主体动作、结束状态、必要的空间延续条件。
保持原有首行图片对齐、镜头切点时刻、运镜与台词 `<d>` 块；保留原 `promptLang`，视频正文使用通用身份。
只调整站位且时长不变时，不重新分配秒数或图片编号。原时间安排无法容纳动作时回到分镜处理，不能仅改提示词伪装能完成。

## 图片已生成时

复核实际图像与修订后的 `frame`。位置、姿态、视线或遮挡受影响的图片需要重新生成并确认。
只改 JSON 不会修改既有图片；图文冲突时应明确列为待更新。
正式视频输入继续使用对应的独立关键帧；带箭头、标签和宫格边框的评审图不加入正式图片编号。

## 完成标准

- 逐镜起始、动作和结束在备注、画面描述、`shot` 与 H3 中一致，并核对跨段承接。
- 正式附件引用仍指向正确的独立关键帧，既有图片中受修改影响的内容已确认或明确列为待更新。
- 时长、节拍、台词、人物和道具引用按项目原有入口校验。
- 如实区分“提示词已同步”“图片已更新”和“视频已验证”，不能用一次静态导出来宣称全部完成。
