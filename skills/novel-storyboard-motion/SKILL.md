# novel-storyboard-motion-04 · 动作与连续状态

**使用顺序：04，按需执行。** 调用使用 `$novel-storyboard-motion`。接收空间安排及表现增强后的最新分镜，复核交接、接触、承重、运动和跨镜连续状态，然后进入最终宫格、关键帧与视频导出。
没有相关问题时可以跳过专门修订，基础连续性仍需检查。发现必须调整空间或切镜时返回对应安排，完成后再次核对受影响动作；编号不是安装依赖，可以直接处理已有项目材料。

把“递过去、扶住、推开、停下”展开成观众能看见的动作过程，保证关键接触、受力和状态变化进入正式分镜。
`{baseDir}` 是本文件所在目录。Agent 负责动作语义；Node.js 18 以上的标准库脚本负责对比结构、提示词保护和修改范围。

## 输入与职责

读取分镜原稿及对应剧本或用户确认的故事说明，确定要处理的集、段或镜头。角色、场景、道具设定、开场站位和实际参考图片有则读取。
这些是项目材料，可以来自任何制作方式；本技能不导入其他技能代码，也不要求读取其他技能文档。

## 编排职责

- 剧情、对白、事件顺序和交接结果以故事为准。拒接、撤回、抛接和交接失败都可能是既定剧情，不能统一改成成功递交。
- 已确认的场景位置、人物开场站位、道具数量与造型沿用原稿。空间不足或机位看不到关键过程时，列出具体调整建议。
- 默认保留镜号、时长、景别、运镜、构图字段、节拍认领和参考图片顺序。必要的动作细化应实现既有事件，不新增故事事件、对白或道具。
- 只有分镜、没有故事说明时，可以检查和解释矛盾；涉及事件结果或动机的修订保持待确认，不能自行选定剧情。

遇到交接、支撑、移动或抛掷时，按动作规则对应章节展开；普通对白镜头不必附加整套物理描述。
涉及持续持物、复合接触、双手操作或连续声源时，执行动作规则中的“连续状态与跨镜继承”：从最近终态继续，先继承仍成立的关系，再写变化。
逐镜执行“逐镜连续性锚点”，核对已确认的光照、画内身份、位置朝向和机位侧。共同设定在当前生成输入中统一交代，逐镜正文保留变化及容易歧义的局部关系；位置随动作更新，独立生成时补齐本次输入需要的事实。
编写表演时执行“字面表达与表演依据”“对白与配角的延续”，保留原表演意图、对白和已建立的背景活动，不自行增加情节。

## 从动作目的到镜头过程

先确认这一镜必须发生什么、结束时谁持有什么或处于什么姿态，再规划接触与运动顺序。
复用原有逐镜 `note`，保留已有备注，补充或更新：

> 起始：最近一次确认的动作阶段、持握与支撑、双手占用、人物姿态和必要的运动方向；本镜需要的空间与光照锚点。
> 动作：谁接触哪里，怎样施力或承重，关键变化按什么顺序发生。
> 结束：物品归属、接触与支撑、位置与动势，以及已改变的启用或损坏状态。
> 接镜：承接上一镜哪些关系仍持续，下一镜还需继续什么；省略或换场说明故事依据。

不靠下一镜的“已经接住”“已经站稳”补造遗漏动作。同场连续时间的段落也要衔接；已经完成的动作不重演，后段事件不提前发生。
动作超出原时长或构图能力时，交付具体的拆镜、延时或机位调整建议，并将受影响镜头列为未解决；不要悄悄改变镜头合同。

一个主要动作可以包含必要的协同与阶段，例如递交中的送出、接住与松手。不要按动词数量机械切镜，也不要把递交、转身、走远和开门同时塞入一镜。

## 写回实际消费端

按照已读取的输入与提示词同步约定，在原稿旁保存修订副本，保留原数据结构和未知字段。

- `cut.frame`：只写本切起始时刻的一个可见状态，明确交接或运动处于哪个阶段。
- `cut.shot`：从该状态展开动作，写清关键过程与终态；保持当前协议语言和人物指代方式。
- `segment.h3Prompt`：同步对应镜头的起点、动作、终态和声音，保留原对齐行、切点、图片绑定、台词及协议结构。
- `cut.sfx`、`segment.soundscape`：动作改变时同步相关声音，不让旧碰撞声继续要求画面发生碰撞。
- `cut.note`：保留编排依据。备注不会自动进入图像或视频提示词，不能只改备注。

将动作修订合并写回原文，替换过期状态，保留关键接触、支撑、变化顺序与终态；不在旧正文后追加另一套动作纠错说明。`shot` 与 H3 按各自实际输入保留必要锚点，`frame` 只呈现切点可见事实，完整复核过程留在备注。
声音、视线和说完后的行为放在台词之外，保留原说话人及画外音安排；具体写回方式遵守输入与提示词同步约定，不新增表演专属字段。
参考图只按已确认职责使用。角色设定图的持物姿态不自动代表当前状态；动作参考只指导已指定的动作或节奏，不顺带引入人物外貌、道具和背景。
已有成片时按实际观察核对边界；单张尾帧只能提供静态状态，运动方向和速度需要结合视频或可靠说明。未实际查看的材料不得写成已观察事实。

## 复核与交付

反向连读修订镜头及前后镜头，必要时追到下一次明确建立状态的位置。逐项检查：

1. 普通递交是否先接触并接住重量、再释放？放置是否先获得台面支撑？抛接是否有明确放手、飞行与接收或落地？
2. 是否无故换手、复制物品、改变朝向或失去支撑？复合接触、双手占用和启用或损坏状态是否继承？看不见的物件是否仍有合理去向？
3. 运动是否有原因、路径、可见反馈与结束状态？静止、继续运动与回稳是否相容？
4. 当前机位是否能看到关键过程和终点？切换角度后是否仍处于同一动作阶段？光照、身份、位置朝向与机位侧是否一致，反应视线能否指向真实对象？
5. 关键帧、镜头正文和 H3 是否说同一件事？声音是否对应接触、释放或持续运转的实际阶段？实际参考图片是否仍然适用？
6. 比喻、成语或情绪颜色词是否会引出故事之外的物体或画面变化？表演方向和可见依据是否一致？
7. 对白是否有合适的声音与视线指导，说完之后是否继续既定行为？仍在画内的配角是否延续原有活动，且没有增加抢戏动作？

对已保存的原稿与修订稿运行：

```bash
node {baseDir}/scripts/motion.mjs review --before <原分镜.json> --after <修订分镜.json> --out <motion-review.md>
```

命令只读取两份分镜，生成 Markdown 对比报告；不替 Agent 编排动作、不改写输入、不判断物理语义成立。
报告逐项列出 6 道程序门：输入与骨架、镜头合同、字段合法性、正文及编排材料、H3 结构与绑定、单边修改与同步提醒。
退出码 2 表示 G02–G05 未通过或 G06 同步待核对；退出码 1 表示 G01 输入或命令错误。按报告逐项处理，再完成上面的语义复核。
未通过时先修正并重跑。需要上游资料、镜头调整或无法确定的同步取舍时，保留具体未解决项，交付状态写为“部分完成”或“待补”，不能宣称全部通过。
G06 因措辞调整而触发、实际无需同步时，应在编排说明中逐条写明镜号、字段和判断依据，同时保留原工具结果，不伪造通过或为了消除提醒而机械改写另一套提示词。
项目已有分镜校验入口时继续运行它；缺少入口则注明未执行，不将其作为本技能的安装依赖。

默认交付：修订分镜副本、对比报告，以及简短的编排说明，列明修改依据、语义复核结果、未解决项和需要更新的图片或导出包。
脚本通过不代表动作正确，也不代表成片已验证。修改关键帧提示词后，已有图片及关联宫格、视频提示词导出包要重新核对或生成；不要交付旧图片配新动作。
