# 检测门与交付

## 六道程序门

| 编号 | 检查范围 | 失败处理 |
|---|---|---|
| G01 输入与骨架 | JSON 可读，集段镜非空，段号唯一，时长和节拍基本合法；范围参数必须同时包含 performance、camera，effects 可选 | 停止比较，退出码 1 |
| G02 故事覆盖与数据保护 | 允许拆并镜头、重新分段、时长和续段站位调整；原场次和节拍顺序、恰好一次的覆盖、已有资产身份、配乐及未知字段保持 | 修正丢失、重复、越界引用或未知数据冲突；不冻结原镜头结构 |
| G03 字段与增强方向 | 表演与摄影必选；必要画面与摄影字段可补齐；重排满足项目单镜和单段时长，枚举与文字类型合法；光影语义由 Agent 判断 | 修正范围、材料或预算，不能通过改全局参数掩盖超时 |
| G04 正文与依据 | 每切 frame、shot 非空；受切级文字或 H3 镜头改动影响的切有起始、动作、结束、接镜、增强依据；摄影改动具备摄影资料 | 补齐并同步实际正文；标签存在不证明内容正确 |
| G05 H3 协议与对白 | 三字段顺序、镜头数量与编号、图片及累计切点合法；重排后重新生成对齐首行，原对白、说话人、场次、发声顺序和配乐保持，台词仍在原事件节拍范围 | 修复协议或对白误改；对照剧本复核精确节拍、身份、口型与画外音归属 |
| G06 逐镜同步提醒 | 画面或摄影改动但对应 H3 镜头未变；H3 镜头改动但另一端未变；声景或音效单边改动 | 核对是否漏同步；等义措辞可解释，但保留提醒与判断依据 |

默认使用 `apply --file storyboard.json --modes performance,camera`，从标准输入读取 `{before, after}`；有正式剧本时增加 `--script`，细分动作时再提供 `scriptBefore`。先核对磁盘文件仍与 `before` 相同，再执行比较；G02–G05 失败或 G06 待核对返回 2，不修改分镜，剧本基线不匹配等输入契约错误返回1。程序门通过才写回原路径并返回 0，仍不代表语义或成片通过。默认只打印报告，`--out` 更新指定报告，不产生版本 JSON，也不能覆盖分镜或正式剧本。
只改另一切的 H3 不能消除当前切的同步提醒。两端文字都改过也不能证明语义一致。
未改动镜头无需为了增强补造备注；frame、shot 和 H3 基本完整性仍覆盖整份增强稿。区分本次修改与范围外既有缺项，不能将部分通过说成整份通过。
提供 `--script` 时，工具读取正式剧本核对在场资产、精确台词节拍与单集目标容差；提供 `scriptBefore` 时追溯动作细分来源。数值对账不能证明动作改写保留了因果与结果。工具不识别实际图片，不模拟摄影路径、物理或人物表情，也不验证全部 H3/Seedance 语法、语言、身份指代及台词容量。

## 五项 Agent 语义复核

按镜头组及具体镜号填写通过、不适用或未解决及其依据，不能把程序生成的待复核清单当成已完成结论。组范围以入口的连续表达单元为准，区分评估镜号与仅供上下文读取的镜号；程序列出的相邻镜头只是修改影响提示，不代表整组范围或已完成评估。
先核对整组观看过程是否落实到镜号，再核对逐镜选择是否来自该判断。有疑点的组合应说明具体选择与取舍；原组合保留时也需说明各镜怎样配合。程序或报告生成脚本只能整理已有判断，不得把“未修改”自动判为“保留成立”；复述原动作加通用理由、镜号覆盖或行数齐全，均不构成评估证据。缺少实质判断的镜头标为待评估。

先检查上游有没有把重要过程省略掉，再判断现有过程是否演得充分。按本场任务检查移动、进入、控物和操作的路径、人物选择及因果；将已有性格落实到行动方式、节奏和回应。发现缺失时应补演，不能把“剧本已省略”“只是走路”“镜头原本如此”当作保留依据。
状态连续、接触清楚和机位可见，只能支持局部安排。还要判断行动原因是否可读，以及切换是否带来信息、关系、情绪或必要持续观察的收益。任务被前后镜修订提前完成或转移后，须重新编排受影响镜头；结构本身可以调整，不能以保护原镜数、时长或续段站位为由留下已发现的缺口。

1. **剧情与收益**：原问题是什么，改动使什么信息或反应更清楚；对白、人物意图、能力、顺序和结果是否保持。
2. **表演与可见性**：说明遗漏及补演后的行动、性格和反应如何可见，复核组首状态、已有触发、跨镜发展与既定结果。触发在反应之前，景别、焦点、时长支持变化，口型与对白相容，既有持物和支撑连续；自然表演可以补写，不新增故事结果。选用条目时核对完整描述，说明采用特征及收益。
3. **摄影与空间**：说明补演后观看过程如何分配到镜号，复核构图、动静、切换及关键反应。重排后更新段级站位、路径、资产引用、图片编号和累计切点；世界锚点与场景开场事实保持，人物移动有既定行动依据。对话原文、说话人和画内或画外归属保持。单镜、单段与单集预算均须复核，不能只靠程序局部时长通过。
4. **特效与连续状态**：已有来源、变化与结果相接，持续或消散有依据；双手占用、支撑、数量及声源阶段没有重置。
5. **消费端与素材**：备注、frame、shot、摄影、局部受光、H3 和声音一致；实际图片与成片按已观察范围判断，列出需更新的材料。

只有未选择的特效增强可按方向标不适用，连续状态仍须复核。表演与摄影不得整项标为“未选择”或以字段未改代替评估；无人镜头可注明表演不适用的具体原因，摄影仍需说明观察任务。相同的保留理由可合并列出镜号，未改动镜头无需补造备注。整组结论与逐镜依据相互关联，可引用而不必重复；全组未改也需说明整组保留依据。缺少整组评估、整组复核或任一必选方向的逐镜评估时为部分完成；程序通过不证明评估已完成。
摄影变化需要空间复核，表演或特效变化需要动作与连续状态复核；本目录提供必要规则，不依赖其他技能才能给出判断。
条目读取与语义适配由 Agent 实际完成，不能把库编号存在、条目数量完整或程序门通过当成适配证明。增强依据应能指出所读条目、采用的可见变化、收益及未采用部分的理由；本次自行编写的表现说明依据即可，不伪称出自资料。

## 完成条件

- 记录实际读取的故事、分镜、相关设定和素材范围，区分确认事实、计划、观察和待核实部分。
- 提供原位更新的正式分镜、程序对比和五项语义结论，不另存分镜副本；对比与说明可以在回复中交付或更新已有报告。增强说明包含各组范围、对应镜号的观看过程、原组合判断、选定调整及前后表达差别，表演与摄影各有逐镜增强或具体保留依据。全组保留时说明现有组合如何完成观看过程；局部改善如实限定收益。报告中的程序结果保持真实。
- 尚有待评估镜头、仅有剧情摘要或模板保留理由时，表达评估尚未完成，交付状态为部分完成或待补。没有修改数量或运镜比例要求，不为了报告好看制造改动。
- 已发现的表演、性格或关键过程遗漏必须有正式正文中的补全与具体镜号；必要的拆并镜、时长重分和站位同步应在本次落实。缺口仍只停留在建议、原稿复述或表情标签时，相应组保持未完成，整体交付为部分完成。
- 缺少决定剧情所必需的事实、用户锁定的结构或项目预算无法满足时，说明具体冲突及已完成范围。没有未解决材料、程序失败或未解释同步提醒后，才声明本次文字增强完成；程序不验证故事语义和实际速度，未提供剧本时也不验证单集目标。
- 修改 frame 或摄影后核对关键帧，修改镜头正文、H3 或声景后更新相关视频导出包。无法查看或重新生成时列为待更新。
- 尚未实际查看生成结果时，不写“效果已验证”“视频验收通过”。
