# 输入适配与实际消费端

## 原结构与修改范围

已有分镜为 `episodes[] → segments[] → cuts[]`，段以 `id` 标识，镜号由段内顺序确定。这里描述既有输入适配，不扩展 JSON schema。
保持未知字段和相对路径，原位更新项目的 `storyboard.json`（沿用已有实际文件名）。修改前对象只在内存中保留，修订对象也在内存中构造；不创建独立增强分镜或临时版本 JSON。

完成语义复核后调用 `node scripts/enhance.mjs apply --file <storyboard.json> --modes performance,camera`，通过进程标准输入传入 `{before, after}` 两个完整对象。程序先核对 `before` 与磁盘内容一致，保护性检查通过才写回 `after`；失败时不改分镜。不要先覆盖文件，再拿同一份内容比较以冒充前后检查。默认报告打印到标准输出，`--out` 可更新项目已有报告；旧 `review --before --after` 只用于已经存在的历史文件。
有正式剧本时增加 `--script <script.json>`。该场角色或道具虽然被旧镜漏登记，只要正式剧本已经列出，就可恢复引用；程序同时核对逐切台词与单集目标容差。
确需把一个既定动作展开为多个节拍时，在内存保存旧剧本，原位同步正式剧本，再通过标准输入提供 `{before, after, scriptBefore}` 三个完整对象。`scriptBefore` 是修改前剧本，`--script` 指向磁盘上的最新剧本，不创建额外版本 JSON。程序将动作细分后的节拍追溯到原事件，原对白和非动作元数据保持；纯插入、删除事件或无法明确对应的多事件替换会被拒绝。动作正文的因果、能力与结果仍由 Agent 复核。比较期间剧本再次变化则拒绝写入分镜；本轮失败时继续修订或恢复本轮剧本修改，不能交付两份不同步的数据。
每次范围必须包含 `performance,camera`，`effects` 可选。下表区分修改的用途，表演与摄影均须评估；摄影范围不授权省略特效选择而展开效果过程。

| 范围 | 允许修改的已有字段 | 缺失时可补充 |
|---|---|---|
| 两项必选方向及可选特效共同需要 | 切的 `frame`、`shot`、`note`、`sfx`；段的 `h3Prompt`、`soundscape` | 同左，依据故事补足缺项 |
| 表演与摄影的视线安排 | 切的 `eyeline` | `eyeline` |
| 摄影调整 | 切的 `size`、`camera`、`lens`、`cameraPosition`、`composition`、`focus`、`stability` | 同左；没有实际空间材料时区分调度计划与观察事实 |
| 摄影说明或已选择的特效 | 切的 `lighting` | `lighting`，仅已有事件造成的受光或必要摄影说明 |

增强所需的拆并镜头、重新分段、时长重分、逐镜资产引用和段级 `blocking` 可以修订。程序按原场次和节拍顺序对账，要求恰好覆盖一次；已有节拍可以重新分配到镜头，单一节拍内部的补演也可在同镜展开。确需细分剧本动作节拍时，同步正式剧本并重新校验认领，不借重复节拍增镜。
场次、故事事实、人物关系、对白原文与归属、结果、资产身份、全局设定、原配乐及未知字段受保护。重新取景只能引用该场已有资产；未知数据须随相应节拍保留，合并时存在冲突则明确处理。场景真正开场的位置与状态仍来自确认材料；续段开场须随新前镜终态更新，程序不以整段文字逐字相等代替事实保护。
程序无法从自由文本确认性格、因果、世界站位、口型和画外音是否保持。提供正式剧本时校验精确台词节拍和单集预算；没有剧本时只保护原镜对应的节拍范围，不能据此声称完成精确剧本对账。重排后检查项目 `params` 的单镜和单段上限，并运行项目已有完整校验；缺少入口时如实说明范围。
允许修改正文不代表允许改变剧情事实；自由文本里的越界只能由 Agent 对照故事判断。修改视线也不能凭空添加被看对象。
`camera` 沿用当前 H3 适配词表，如 `Static Shot`、`Push In`、`Pull Out`、`Arc Shot`；`size` 沿用五档景别，`stability` 沿用 `stable`、`slight-shake`、`handheld`。完整合法词表由本目录工具内置；其他格式不自动迁移。

## 关键帧与 Seedance

关键帧消费 `frame`：中文景别与角色名，单个切点状态；参考图锁定身份与设定，不照搬多视图排版。
围绕本镜观看重点，将表情、视线、姿态和摄影调整融入已有画面，删除被替代的旧句并合并同义说明。`frame` 只保留切点可见的反应，反应发展进入视频正文；不要在原文后连续追加表演、摄影或特效补充。
Seedance 导出消费 `shot`、摄影字段、既有 `blocking` 及声音/光影字段，不消费 `note` 作为动作正文。`shot` 沿用中文与通用身份，不添加秒数、镜头编号、图片编号、台词或协议包装符号，这些由现有导出流程处理。
条目编号、选择理由、被舍弃方案和待复核项留在 `note` 或增强说明。按表达需要保留细节，不以字数或新增描述数量衡量增强；整理后核对原定情绪、人物关系和连续状态是否仍然清楚。独立生成的图片与视频须分别具有必要说明，不能跨输入删除它们各自需要的事实。
增强动作或局部受光进入正文，不能只放在备注。修改关键帧描述或摄影安排后核对旧图片，列出重出范围；即使旧图可沿用，也给出判断依据。

## H3 逐镜同步

H3 是单独保存的段级提示词，必须同步对应镜头，而不是随便改一处就视作全段同步。
沿用输入的英文或中文模式和三字段顺序。镜头结构未变时保护原对齐首行、编号、切点和图片绑定；重排后按新结构重新生成这些协议内容，不能拿旧提示词只改几个动作词。
保留原配乐正文。台词随原有剧情节拍重新绑定，原文、说话人、发声先后与画内或画外归属保持；不移入其他事件或声景字段。程序对比原文、说话人、场次、顺序和原节拍范围，提供 `--script` 时还核对精确台词节拍；口型与画外音归属仍须语义复核。
声音只写在原有适当位置：对白保留原块，动作声与环境声同步声景，配乐保持。Seedance 声景变化时核对 H3 声景，反方向亦然。
程序逐切提示单边修改，但不能确认两端改的是同一件事；仍要连读 `frame`、`shot`、摄影字段、H3 与声音。

## 空间、动作与实际素材

摄影改变后保持世界锚点、人物站位和关系轴可理解，观察方向变化不等于人物换位。路径受阻、关键过程出画或画内资产清单不相容时，先修正本次摄影增强。
表演与特效改变后核对手部占用、接触、支撑及效果阶段；一端被手握住、另一端仍接触台面时两种关系同时存在。画外物品延续最近状态，换手、松手、放置或状态恢复需要过程依据。
以实际接受的成片边界为准；只有尾帧时不声称知道速度、声景或被遮住的接触。计划、观察和用户转述分别记录。
本目录不自动读取或安装其他技能。项目已有完整校验入口时执行其检查；没有入口时报告未执行，并保留本工具的有限结论。
