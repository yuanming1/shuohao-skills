# novel-storyboard-enhance-03 · 情绪与镜头增强 · v2

**使用顺序：03，按需执行。** 调用使用 `$novel-storyboard-enhance`。进入本步后，必须同时处理表演与摄影两个方向，先评估整组表达，再逐镜增强，最后连读复核整组效果；既定特效增强可选，再进入 04 的动作与连续状态复核。
原稿表现已经成立时可以跳过本步；改动机位、构图或手部表现后，先核对受影响的空间与占用关系。编号不是安装依赖，空间事实可以直接来自用户材料。

让已有故事获得充分的表演与镜头表达。先找出原稿没有演出的行动、反应和人物特点，再补足过程并安排摄影；不能把原稿的省略和镜头结构视为已经确认的最佳方案。原稿已经充分时允许保留，理由须来自具体表达。
`{baseDir}` 是本入口所在目录。Agent 完成编排与语义判断，Node.js 18 以上的标准库工具只做保护性对比。

## v2 新增内容（2026-10-20）

- 成组评估：按连续对话、事件或情绪变化确定阅读单元，允许跨相邻生成段，判断信息推进与注意力安排。
- 表演与摄影协同：补充跨镜情绪发展、听者反应、内外反打选择，以及构图和动静变化的收益判断。
- 整组复核：逐镜增强后连读检查表达、节奏与关键反应，在原有增强说明中记录整组结论。
- 交付同步：更新语义复核提示与《雪站回灯》案例；沿用既有数据结构与六道程序门，保护故事边界并允许必要的镜头重排。

本次 v2 补充（2026-10-20）：先确定整组观看过程，再决定各镜保留或调整；有疑点时比较具体摄影选择；保留结论不得由未修改状态自动推导；整组交付说明修改前后的表达差别。《雪站回灯》增加多镜构图与景别协同调整的示范。

## 输入、范围与读取

输入为已有 `storyboard.json` 和对应剧本或用户确认的故事说明。`performance`（表演）与 `camera`（摄影）必须同时选择，`effects`（特效）按需求与既定效果的问题选择，并确定集、段及镜头范围；未指定范围时评估整份输入分镜。
用户只说“增强”时，同样执行表演与摄影两项评估。每镜分别判断增强收益，原稿已经成立的方向可以保留，但须在增强说明中按镜号记录理由；相同理由可合并列出镜号。必选方向不要求每镜都改表情或增加运镜，也不能用某一方向没有修改代替该方向的评估。程序的 `--modes` 只检查范围声明，不证明两项评估实际完成或语义没有越界。

| 时机 | 读取内容 | 使用范围 |
|---|---|---|
| 开始任务 | 本入口、[输入与同步约定](references/handoff.md)、[检测门](references/gates.md) | 先了解允许修改范围、实际消费端和交付条件 |
| 开始两项必选评估 | 读取 [performance.md](references/performance.md) 和 [camera.md](references/camera.md)；选择特效时另读 [effects.md](references/effects.md) | 表演与摄影规则均必读，相关约束在本目录内完整提供 |
| 选择情绪与表演条目 | [情绪、眼神与人物表情库](references/expression-library.md) 的相关章节；需要反应过程时读取 [微表情 01–50](references/microexpression-library.md) 的对应条目 | 先依据故事选择情绪，再取当前景别能看见的具体反应；不只读取条目名称 |
| 选择镜头条目 | [镜头与运镜库](references/camera-library.md) 的相关章节 | 按观察任务选择景别、视角、情绪化运镜、表情特写或复合配方；涉及移动时查看运动关系，核对主体、机位、环境参照和终点 |
| 确定剧情依据与镜头组 | 分镜原稿及匹配场次的剧本、节拍与对白，或已确认故事 | 确认人物意图、触发事件、能力边界及结果，确定连续表达单元后再设计增强 |
| 确定连续状态 | 目标镜头、前后镜头及连续段边界 | 追查最近的持物、双手占用、支撑、视线和声源；来源更早时继续向前读取 |
| 涉及设定与空间 | 已提供的相关角色卡、场景/道具卡、`art.json`、`staging.json` 对应部分 | 沿用造型、材质、灯光、场景锚点、开场站位、行动限制及法术设定，不加载无关资料 |
| 已有参考与成片 | 目标镜头实际绑定的图片、已指定用途的动作/摄影参考和可查看成片；必要时上一段接受的结尾 | 区分真实观察、文字计划和用户转述；单张图片不能证明完整动作、速度或声音 |

缺少故事依据时只检查已有矛盾，不选择人物动机、能力或事件结果。缺少关键设定或无法查看素材时，继续已知部分，将受影响镜头列为待补，不假装已经观察或确认。
来源说明只在需要追溯方法时读取，示例只在需要写法参考时读取；运行不依赖来源网站、本机下载文件或任何兄弟技能。

三个条目库共收录镜头相关 32 条、情绪与眼神 10 条、基础表情 39 条、连续微表情 50 条。每次同时评估表演与摄影，先明确整组表达与每镜任务，再按两类条目库的索引读取相关章节与具体描述，决定是否采用；需要反应过程时读取对应微表情条目。故事没有合适条目时可以自行细化已有反应，注明是本次编写。
在受影响镜头原有 `note` 的“增强依据”中记录所选编号、实际采用的特征及必要的舍弃理由；本次自行编写的内容也要区分。不新增 JSON 字段，不把原文件里的道具、人物关系或情节随模板带入。

## 先评估整组表达

先对照故事与角色设定检查遗漏。人物在争取什么，性格如何影响他接近别人、进入空间、执行动作和回应信息，原稿是否只有结果、没有能让观众理解的过程？允许为既定意图编写原稿未逐字写出的自然表演、行动细节和反应；把它们落实到正式正文，不能只补评语、微表情标签或条目编号。
上游写了“省略”也须重新判断。进入、行走、带球、操作等按本场的表达任务处理：需要理解路径、控制、接触、关系变化或人物选择的过程应补全；没有信息变化的重复路程可以压缩。无需实时拍完整距离，但起因、关键过程与结果必须足以理解，不能按“只是走路”决定省略。剧本的省略文字与补全方案冲突时，同步修订该动作的呈现安排，保留原事件、对白、先后和结果，并在增强说明中指出修改依据；无需调用其他技能。

按一段连续对话、事件或情绪变化确定镜头组，说明组首已知信息、组尾应呈现的既定变化，以及各镜承担的任务。一组可以跨相邻生成段，不按固定镜头数量或生成时长机械分组；表达任务已结束或场次、时间关系中断时重新判断边界。
镜头组作为表达设计与复核单位。按补全后的观看过程协同调整观察重点、景别、机位、构图和内外反打；必要时拆并镜头、重新分段、分配时长与逐镜资产引用，续段开场从新前镜终态承接。人物的场景开场事实、对白归属、知情顺序和既定行动结果保持。用户只指定部分镜头时，读取所在组作为上下文，只修改授权范围；结构调整影响范围外内容时明确报告影响，不扩大任务。只有单镜材料时先补足可知部分，无法判断的前后关系列为待补。

按照 [摄影规则](references/camera.md) 先在已有增强说明中确定整组观看过程：观众先知道什么，随后注意谁或什么，何处延续或改变情绪与关系，最后确认什么；将这些任务对应到具体镜号，再决定逐镜改动。结合 [表演规则](references/performance.md) 检查反应如何跨镜发展。整组判断须说明现有摄影组合能否完成上述过程，不能只概括剧情后直接挑选可加运镜的镜头。
对任务重复、重点不明或关键反应不可见的组，按摄影规则比较相关镜头的具体选择与取舍。重复构图可以服务于等待、强调或持续观察，不要求每镜都改变景别、运镜或表情，也不规定每组必须提出多个方案或达到修改数量。
组内发现的问题应在本次增强中解决：取景、焦点或表演足够时落实到镜头；需要增加反应阶段、拆并镜头或重分时长时，按 [摄影规则](references/camera.md) 直接修订正式分镜并同步消费端。不能为了维持原镜数和原时长，只追加表情或把必要过程继续留作建议。新的镜头仍认领原有连续节拍且不重复；单一节拍内可以延长合理动作过程，确需细分剧本节拍时先同步正式剧本与认领关系。只有需要决定新的剧情事实、缺少关键材料、用户明确锁定的结构或项目时长上限无法满足时，保留具体未解决项。

## 选择有收益的改动

依据整组表达与每镜任务判断原问题：情绪没有触发、反应看不见、镜头组合没有引导注意力、运镜缺少目的、特效没有过程，或正文与图片矛盾。选择能解决问题的最小修改；最小修改可以涉及组内多镜的配合，不等于优先保留原摄影再追加表情或运动。
保留故事事实、人物关系、对白及声音归属、事件先后与结果、场次、已确认的场景开场事实、资产身份、原配乐与未知字段。镜号、切数、切点、时长、已有节拍的分镜分配、逐镜可见资产和续段站位均可按增强需要调整，不能把它们与故事事实一起冻结；用户明确锁定的项目约束仍须遵守。
表演应将已有性格和意图落实为可见的行动方式、与他人的距离、注意力、节奏及触发后的反应；允许补写实现既定事件的必要过程。选择特效后可以展开已经设定的变化。不新增台词、事故、人物关系、攻击结果或能力，不让动作暗示原本没有的接受、拒绝、伤愈或承诺。
摄影增强允许修改已有摄影字段，并同步正文；表演细化涉及机位调整时，需写明摄影收益并复核空间，不能顺带改变机位。特效增强可补充已有事件造成的局部受光，不能重设全场天气、时间或全局色调；摄影范围不代替可选的特效过程增强。

在修改切的既有 `note` 中保留原说明，并写明：

> 起始：本切开始的可见状态、持物与必要支撑。
> 动作：触发原因、反应或视觉变化的顺序。
> 结束：本切结束的表演、道具与运动状态。
> 接镜：继承的关系及下一镜继续的阶段。
> 增强依据：原问题、选定方向和本次改善；必要时指出空间、动作或素材的待复核项。

未增强镜头不必修改原有备注，在增强说明中记录表演与摄影的保留理由即可。理由须关联该镜具体可见内容及其与前后镜的关系，并确认必要过程与性格表达已经充分；仅复述原动作或写“固定镜头便于观察”不足以证明原方案成立。脚本不能按未修改状态自动生成保留结论。发现的遗漏须有实际修改及对应镜号；未补足时标为未完成，不能用保留原结构作理由。

## 同步与复核

按照已读取的输入与同步约定，读取项目唯一正式分镜 `storyboard.json`，在内存保留修改前对象并编写修订后的完整对象，完成本轮语义复核后通过 `apply` 校验并写回同一路径。沿用用户已有文件名（如 `<剧名>-storyboard.json`），不另存 `-enhanced.json`、`-motion.json` 或其他分镜版本。将增强融入 `frame`、`shot`、相关摄影/光影/声音字段及 H3 对应镜头，合并重复描述并替换旧句；选择依据和复核过程留在备注，正式画面与动作必须进入实际消费端。
关键帧只描述切点，视频正文从切点继续；相邻镜头继承最近终态，画外持有不等于消失，已经完成的动作不重演。拆并镜头或重分时长后，重新生成段号、图片对应、H3 对齐首行与累计切点，逐句对白随原节拍保留原文、说话人与先后。复核项目单镜、单段和单集预算；不通过调整全局参数掩盖超时。
修改机位、构图或人物调度后复核轴线、路径、遮挡与画内资产；新增表演动作后复核双手占用、接触、支撑和时长。与既定空间或动作相冲突时修订本次安排；单张参考图不能证明完整路径，用户明确锁定的事实不得改写。
逐镜同步后连读整组，检查注意力转移、表演发展和镜间节奏是否仍服务于原定表达，关键反应与结果是否可读；必要时连读组外相邻镜头。若本次或先前的动作、空间修订使某镜任务提前完成或转移，重新评估其保留理由与相邻切换，不能仅将正文改为“持续保持”。必要重排尚未处理时保留整组未解决结论，已完成的局部收益按实际范围说明。复核具体要求见摄影与表演规则，不能以各镜单独成立代替整组判断。

运行原位更新，标准输入提供内存中的 `{before, after}` 两个完整对象，不将它们另存为版本文件：

```bash
node {baseDir}/scripts/enhance.mjs apply --file <storyboard.json> --script <script.json> --modes performance,camera
```

`--modes` 必须包含 `performance,camera`；本次还增强既定特效时使用 `--modes performance,camera,effects`。缺少任一必选方向时程序拒绝处理。不得仅添加参数而省略对应评估；摄影改动仍须有实际收益与空间依据。
有正式剧本时通过 `--script` 一并校验在场资产、逐句对白与单集预算；只有故事说明时可省略，但须说明检查边界。确需细分一个动作节拍时，先在内存保存旧剧本，再同步正式剧本；标准输入增加 `scriptBefore`，形成三个成员的 `{before, after, scriptBefore}`。程序追溯动作细分后的节拍来源，不允许借此改对白、在场身份、剧情钩子、结果或时长目标。修订后的动作是否保持原事件仍须语义复核。
工具核对 `before` 与磁盘当前内容一致，六道程序门通过后才将 `after` 写回原文件；失败或 G06 待核对时保留原文件。默认向终端输出比较报告，不新建文件；需要留档时用 `--out <既有报告.md>` 更新同一份报告。退出码 0 仅表示程序门通过并完成原位更新，2 表示门失败或同步待核对且未写入，1 表示输入、版本冲突或命令错误。旧 `review --before --after` 仅保留给已有历史文件做只读比较，不是默认制作流程。
逐项处理六道程序门，再按检测门文档完成五项语义复核，按镜头组及具体镜号记录通过、不适用或未解决及其依据。程序列出的相邻镜头是修改影响提示，不是自动划定的完整镜头组。
项目已有完整分镜校验入口时继续运行，缺少入口则注明未执行，不将它设为安装依赖。改变摄影后，原镜头配方若不再相容也要列为待处理。

## 交付条件

交付已原位更新的 `storyboard.json`，对比结果与增强说明写入本次回复或更新项目已有报告，不创建新的分镜版本。说明实际读取材料、评估范围、是否选择特效、每处收益、五项语义复核结论、待更新图片与导出包，以及未解决项；无需新增 JSON 清单。后续动作复核、报告合成和画布导出继续读取同一份 `storyboard.json`，相关现有报告和导出包从它重新生成。
增强说明中为各组简要记录镜号范围、对应镜号的观看过程、原摄影组合的问题或保留依据、选定调整与整组复核结论；区分仅供上下文读取的镜号。说明修改前后观众注意对象、关系理解或情绪发展的具体差别；仅改善措辞、局部表演或单镜取景时如实限定收益，不能称为整组镜头组合已重构。全组未改时说明现有组合怎样完成观看过程。逐镜说明可以引用该结论，不必重复整组文字或写入未改镜头的 `note`。
表演与摄影必须各有覆盖评估范围的逐镜结论：增强、保留及理由，或待补。说明发现了哪些遗漏，如何补成可见的性格、行动与反应，落实到哪些新镜号及提示词；发生重排时记录新旧镜号对应与时长变化。整项没有修改时须证明原稿已充分，不能仅写“未选择”或“未改变字段”就宣告完成；只完成其中一项时交付状态为“部分完成”。
G06 是同步提醒：若只是等义措辞而无需另一端改动，逐条列出镜号、字段和理由，保留原程序结果。不能为了消除提醒机械改词或伪造通过。
有未通过检查、未解释同步提醒、缺少整组评估或复核、尚待评估的镜头、关键缺失材料或必要镜头调整时，交付状态为“部分完成”或“待补”。镜号覆盖与报告行数只证明材料覆盖，不能证明完成了表达判断。未实际查看图片或视频时，只能声明文字增强与检查完成。

建议使用位置：分镜初稿 → 空间初步安排 → 表现增强 → 动作与连续状态复核 → 正式出图和视频导出。
